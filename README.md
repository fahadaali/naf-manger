# naf-manger — نظام إدارة العملاء

منصةٌ من منصات ناف. تُدير العملاء والعملاء المحتملين والقضايا والمسوّقين
والعمولات، وتعرض لوحةَ تحكّم وتحليلات.

والدخول **مركزيّ**: الهوية في `naf-id`، ولا كلمةَ مرورٍ في هذا المستودع
ولا في قاعدته. والتصميم من سجلّ `naf-ui` — لا لونَ يُنتقى هنا ولا مقاس.

---

## البنية

| الطبقة | التقنية |
| --- | --- |
| الواجهة | React 18 + TypeScript + Vite + Tailwind v4 |
| الخادم | Cloudflare Worker واحد — `worker/index.js` |
| القاعدة | Cloudflare D1 (SQLite) |
| الملفّات | Cloudflare R2 — الصور والمرفقات |
| الجلسات | Cloudflare KV — تقرؤها `naf-auth` |
| المصادقة | `naf-auth` مقابل المركز `naf-id` عبر OIDC |
| الرسوم | Chart.js + react-chartjs-2 |
| الأيقونات | Lucide — حصراً، وبالمعنى المسجَّل في `naf-icons.md` |

**Worker واحد لا Pages.** ترتيب `worker/index.js` هو الحراسة نفسها: ما قبل
`authenticate` مكشوف وما بعده محميّ، فكلُّ مسارٍ يُضاف يقع بعده ما لم
يُقصد غير ذلك صراحةً. و`run_worker_first = true` في `wrangler.toml` هو ما
يمنع تقديمَ `index.html` قبل الحارس.

```
worker/index.js        نقطة الدخول — الحارس والمسارات والأصول
worker/lib/            المنطق: الموارد والصلاحيات والاستعلامات والملفّات
src/                   الواجهة
src/registry/naf/      نسخةٌ من سجلّ naf-ui — لا يُعدَّل يدوياً
migrations/            هجرات D1، للأمام فقط
```

## التشغيل محلياً

```bash
npm install

# أسرار التطوير — انسخ المثال واملأ سرّ المنصة من لوحة المركز
cp .dev.vars.example .dev.vars

npm run dev        # خادم Vite للواجهة وحدها
npm run preview    # wrangler dev — الـWorker والحارس والقاعدة معاً
```

`npm run dev` يخدم الواجهة ولا يشغّل الـWorker، فنداءات `‎/api/*` تسقط فيه.
ولتجربة الحراسة والمسارات استعمل `npm run preview`.

```bash
npm run migrate:local    # تطبيق الهجرات على قاعدة D1 المحلية
npm run migrate:remote   # وعلى البعيدة
```

## قبل الدفع

```bash
npm run typecheck   # tsc — يمسك ما لا يمسكه البناء
npm run lint        # eslint
npm test            # على SQLite فعلية، ويحرس خصوصية خلاصة التحليلات
npm run build
```

**البناء وحده لا يكفي.** `esbuild` داخل Vite يحوّل ولا يفحص الأنواع، فخطأٌ
مثل `TS2440` (تصادمُ اسمٍ مستورَد مع مُعرَّف محلّي) يمرّ منه صامتاً — وقد
مرّ فعلاً إلى الإنتاج مرّةً، وكان يجعل شاشةَ الإعدادات تستدعي نفسها بلا
توقّف حتى يعلق المتصفّح. ولذلك يمرّ سير النشر بـ`lint` و`typecheck` قبل
`build`.

## النشر

يقع في `.github/workflows/deploy.yml` عند الدفع إلى `main`: تُنشأ الموارد
إن لم تكن — D1 وKV وR2 — ويُحقن معرّفاها في `wrangler.toml`، ثم تُطبَّق
الهجرات ويُبنى ويُنشر.

والسرّ الوحيد يُضبط مرّةً بيدك، ولا يُكتب في `wrangler.toml` أبداً:

```bash
wrangler secret put AUTH_CLIENT_SECRET
```

ومتغيّرات `wrangler.toml` غيرُ السرّية: `PLATFORM_ID` و`AUTH_ISSUER` و
`DEFAULT_ROLE` و`BOOTSTRAP_ADMIN_EMAIL` — وشرحُ كلٍّ منها فوقه هناك.

## المصادقة والصلاحيات

**المصادقة مركزية والصلاحيات موزّعة.**

المركز يقرّر من يدخل، ولا يقرأ دور العضو في هذه المنصة في أي قرار. وما
يملكه الداخل يقرّره جدول `members` في D1 وحده، وافتراضاتُ الأدوار في
`worker/lib/roles.js` — وهو الحاكم في كل طلبٍ محروس.

والأدوار ثلاثة: `admin` و`lawyer` و`staff`.

**ولا يُنشأ عضوٌ من هذه المنصة.** الصفّ يُدرَج بأول دخولٍ من المركز
ومفتاحُه `sub` القادم منه، ومن بعده تُدار الترقيةُ والإيقاف من شاشة
المستخدمين. وصاحبُ `BOOTSTRAP_ADMIN_EMAIL` يُنشأ `admin` عند أول دخوله —
وينشئ ولا يرقّي، فيلزم ضبطُه قبل ذلك الدخول.

وتبديلُ الدور يمحو الصلاحياتِ الدقيقة معه فيسري افتراضُ الدور الجديد: عضوٌ
رُقّي وله `perms` محفوظةٌ من دورٍ أدنى كان يبقى على صلاحيات الأدنى، فيُقرأ
دورُه شيئاً وتعمل صلاحيتُه شيئاً آخر. والإيقافُ يُرجَع، وحالتُه تُعرض في
الجدول — ولا حذفَ لعضو: صفُّه يُيتّم سجلَّ الأنشطة.

### الإعدادات — ما يخرج للجميع وما لا يخرج

`GET /api/settings` **بلا تصريح**، وذلك مقصود: `useSettings()` تُغذّي كلَّ
منسدلةٍ في نماذج العملاء والقضايا والمحتملين، فحجبُه يُفرغ نماذجَ الموظّف.

فالمفرداتُ تخرج للجميع لأنها مفردات، وما تحتها من إعدادٍ خاصّ — و`emailSettings`
اليوم وحدها، ومعها كلمةُ مرور SMTP — يُقصّ لمن لا يملك `settings.read`.
والقصُّ في `readSettings` لا في الشاشة: من نادى المسار بيده يقرأ ما يردّه
ذلك السطر لا ما ترسمه شاشة. وما يُضاف من سرٍّ يُضاف إلى `PRIVILEGED_KEYS`،
والأولى به `wrangler secret` كأسرار Zoom وبيسكامب.

## ربطُ Zoom

اجتماعاتُ Zoom تُنشأ من الـWorker لا من المتصفّح: سرُّ المزوّد لا يُشحن في
حزمةٍ يقرؤها كل زائر. وتلزمه ثلاثةُ أسرارٍ من تطبيق **Server-to-Server
OAuth** في لوحة مطوّري Zoom:

```bash
wrangler secret put ZOOM_ACCOUNT_ID
wrangler secret put ZOOM_CLIENT_ID
wrangler secret put ZOOM_CLIENT_SECRET
```

وغيابُ أحدها غيابُ الربط: المسار يردّ `not_connected` والشاشة تقول «غير
مربوط»، ولا يُفبرك اجتماع.

## شاشات العرض

`الإعدادات ← العرض والمراقبة` تُنشئ رابطاً لكل شاشة:
`https://<النطاق>/display/<رمز>`. يُفتح بلا تسجيل دخول ويُبطَل بالحذف.

وما خلفه **إحصاءاتٌ مجمَّعة وحدها** — أعدادٌ ونسب — ولا اسمَ عميلٍ ولا رقمَ
قضية ولا مبلغ. والرابط يعيش في شاشةٍ يراها كلُّ من يمرّ، فما خلفه يجب أن
يحتمل ذلك.

## قراءةُ التحليلات (Workers AI)

فوق شاشة التحليلات لوحٌ يقرأ الأرقام نيابةً عمّن يفتحها: أين يتسرّب
المحتملون، وأيُّ نوعِ قضايا يربح، وأيُّ شهرٍ تراجع.

والاستدلال على **Workers AI** — داخل شبكة Cloudflare نفسها التي تحمل
المنصة وقاعدتَها. فلا مفتاحَ مزوّدٍ يُدار ولا يُسرَّب، ولا خروجَ إلى طرفٍ
ثالث. وهو ارتباطٌ `[ai]` في `wrangler.toml` لا سرّ، فلا شيءَ يُضبط باليد.

**وما يُمرَّر إليه أرقامٌ مجمَّعة وحدها** — لا اسمَ عميلٍ ولا رقمَ هوية ولا
رقمَ قضية ولا بريدَ أحد ولا مبلغاً منسوباً إلى شخص. والخلاصةُ كلُّها في
دالّة `buildDigest` في `worker/lib/insights.js`، تُقرأ في موضعٍ واحد. وهذا
مكتبُ محاماة: الشرطُ لا يُترك لتعليقٍ يقوله، فـ`tests/insights.test.mjs`
يزرع القاعدة بأسماءَ وبُرُدٍ وأرقامِ قضايا ثم يفتّش نصَّ ما وصل الطراز
حرفيّاً، وسقوطُه يوقف النشر.

والناتج يُخبَّأ ببصمةِ الأرقام: أرقامٌ لم تتبدّل لا تُستدلّ مرّتين، وتبدُّلُ
رقمٍ واحدٍ يُبطل الخبيئة. و«إعادة القراءة» تتخطّاها.

### الطراز: Claude، وWorkers AI احتياطاً

كلُّ نداءٍ يمرّ بـ`worker/lib/ai/model.js`، بمستويين:

| المستوى | الطراز | لماذا |
|---|---|---|
| `fast` | **Claude Haiku** (`claude-haiku-5-5`) | ربطُ دفعات وافق، والتصنيف، واستخراجُ الحقول، واقتراحُ الربط، وفهمُ الألفاظ — أسئلةٌ مغلقةٌ قصيرة |
| `write` | **Claude Sonnet** (`claude-sonnet-5-5`) | ملخّصُ القضية والعميل، والموضوعُ المقترح، والاستبصارات — صياغةٌ عربية |

ويلزمه سرٌّ واحد:

```bash
wrangler secret put ANTHROPIC_API_KEY
```

**وبلا المفتاح يعود كلُّ شيءٍ إلى Workers AI** (`AI_MODEL` في `wrangler.toml`)
كما كان — ويعود إليه كذلك عند سقوطٍ عارض لنداء Claude. والطرازان يُبدَّلان بلا
نشر شيفرة: `AI_MODEL_FAST` و`AI_MODEL_WRITE`. والتفكيرُ مطفأٌ والجهدُ منخفض:
أجوبةٌ قصيرة لا تحتاجه، ولا حرارة (إصدار الواجهة الحاليّ يردّها).

**ومع المفتاح تخرج النصوصُ إلى Anthropic** بدل بقائها في شبكة Cloudflare. وما
يخرج هو ما كان يخرج — لا رقمَ هويةٍ ولا جوّال، والحدودُ عند كلّ مستدعٍ كما هي.

## الربط ببيسكامب

`الإعدادات ← إدارة المستخدمين والبيانات ← الربط ببيسكامب`. وبياناتُ العملاء
القديمة هناك موزّعةٌ على مشاريع: بعضُها إداريٌّ داخلي، وبعضُها عملُ عميل.

**والذي يفرّق بينهما ملفّ «بيانات المشروع»** — وهو في كل مشروعِ عميل. فوجودُه
يرجّح `client` وغيابُه `internal`، **والترجيحُ اقتراحٌ لا حكم**: الشاشة تعرضه
ويصنّف من يفتحها بيده، وما صنّفه لا ينقضه مسحٌ لاحق.

**واسمُ الملفّ يتبدّل** — وقد تبدّل: كان «ملخص القضية». فالعناوينُ المقبولة
قائمةٌ تُعدَّل من الشاشة وفيها الاسمان معاً، لأنّ مشاريعَ سنينَ ماضية لم
يُعَد تسميةُ ملفّاتها. وملفٌّ عُرف مرّةً لا يضيع بإعادة تسمية: معرّفُه عند
بيسكامب لا يتبدّل، فيُعرف به ويُقال في الشاشة إنّ عنوانَه الجديد كذا —
ليُضاف إلى المقبولة بدل أن ينقطع الاستيراد صامتاً.

**والاسمُ الجاري يبلغ ما حُفظ من قبل.** افتراضُ الشيفرة يكفي مكتباً لم يضبط
عناوينَه بيده، ولا يكفي من ضبطها: المحفوظُ في `system_settings` يُقرأ كما هو.
فهجرةُ `0015` تُدخل «بيانات المشروع» أوّلَ القائمة المحفوظة وتُبقي ما بعده —
وإلا بقي المكتبُ يبحث عن اسمٍ لم يعد موجوداً، فتظهر المشاريعُ الجديدة بلا
ملفٍّ وتُصنَّف `internal` ولا يقول أحدٌ لِمَ. والقديمةُ منها ينجّيها معرّفُ
الملفّ، أمّا مشروعٌ لم يُمسح قطّ فلا معرّفَ له.

والاتّجاه واحد: **يُقرأ من بيسكامب ولا يُكتب فيه**. فصلاحيةُ القراءة تكفي،
وخطأٌ في المنصة لا يُفسد وثيقةً أصلية عند العميل. (ولوحةُ العملاء المحتملين
أدناه وحدها تكتب — في مشروعها وحده.)

يلزمه تطبيق OAuth يُسجَّل مرّةً في
[launchpad.37signals.com/integrations](https://launchpad.37signals.com/integrations)
برابط عودة `https://<النطاق>/api/basecamp/callback`، ثم ثلاثةُ أسرار.

**ورابطُ العودة يُطابَق حرفاً.** والمنصة تشتقّه من العنوان الذي فُتحت منه
(`url.origin` في `basecamp/oauth.js`) — فمن يربط من `crm.naflaw.sa` يلزمه
`https://crm.naflaw.sa/api/basecamp/callback` مسجَّلاً هناك. والربطُ من
عنوان `workers.dev` أصلٌ آخر، فيحتاج تسجيلَ رابطه هو.

```bash
wrangler secret put BASECAMP_CLIENT_ID
wrangler secret put BASECAMP_CLIENT_SECRET
wrangler secret put BASECAMP_TOKEN_KEY   # مفتاحٌ من عندك، تُعمَّى به الرموز المحفوظة
```

وغيابُ أحدها غيابُ الربط: الشاشة تقول «لم يُسجَّل التطبيق» وتسمّي الناقص، ولا
يُستورد شيء. وتبديلُ `BASECAMP_TOKEN_KEY` يُبطل الربط القائم فيُطلب ربطٌ
جديد — ولا يُفقد شيءٌ ممّا استُورد.

#### أو من لوحة Cloudflare، بلا طرفيّة

`dash.cloudflare.com ← Compute (Workers) ← naf-manger ← Settings ←
Variables and Secrets ← Add`

ولكلٍّ من الثلاثة: النوع **Secret**، ثم الاسم، ثم القيمة، ثم **Deploy**.
واختيارُ `Secret` لا `Text` هو ما يمنع ظهور القيمة بعدها في اللوحة أو في
`wrangler` — وسرُّ التطبيق يُعرض مرّةً عند بيسكامب ولا يُعرض بعدها.

والأسرارُ تبقى عبر النشرات: سيرُ النشر يُحدِّث الشيفرة ولا يمسّها. ولو
مُحيت يوماً فالعَرَض ظاهر — الشاشة تعود تقول «لم يُسجَّل التطبيق».

ورمزا الوصول والتجديد يُحفظان في D1 معمَّيَين بـ AES-GCM. وذلك يحمي من تسرّب
نسخةٍ من القاعدة، لا من Workerٍ مخترَق — من ملك تنفيذ الشيفرة ملك المفتاح معها.

### ترتيب العمل

`اتّصال ← مسحٌ وتصنيف ← خريطةُ حقول ← معاينة ← تنفيذ ← ثم تُفتح الآلية`

**ولا تُكتب في قاعدة العملاء كلمةٌ قبل معاينةٍ رآها صاحبُ المكتب.** المعاينة
تقرأ الملفّات وتقول ما سيقع — كم عميلاً يُنشأ، وأيُّ قضيةٍ تُحدَّث وفي أيّ
حقل، وأيُّ مشروعٍ تعذّر ولماذا — ولا تكتب حرفاً.

### خريطة الحقول

«بيانات المشروع» حقولٌ معنونة: `اسم العميل: …`. والعناوين تختلف بين مكتبٍ
وآخر، فتُربط من الشاشة بحقول المنصة وتُحفظ في `system_settings` — بلا نشرِ
شيفرة. والتشكيلُ والتطويلُ وصورُ الألف لا تُهمّ: تُطابَق موحَّدةً،
فـ«ملخّص القضيّة» و«ملخص القضيه» عنوانٌ واحد.

والافتراضُ يعرف صيغتَي العناوين: «نتيجة المشروع» و«نتيجة القضية» — فالملفّ
الجديد والقديم يُقرآن بلا إعادة ضبط.

### رقمُ المشروع ورقمُ القضية لدى الجهة

**رقمُ المشروع هو معرّفُه في بيسكامب** — الثابتُ في رابطه
(`3.basecamp.com/…/projects/<المعرّف>`). وهو `cases.case_number` لكلّ قضيةٍ
مستوردة، وبه تُطابَق: بربط المشروع السابق، ثمّ برقمها = معرّفه. **ولا يُقرأ
من الملفّ أبداً.**

و«رقم القضية» في «بيانات المشروع» **رقمُها لدى الجهة المختصة** — محكمةٍ أو
شرطةٍ أو نيابة — معلومةٌ للتوثيق تتكرّر بين مشاريع وتغيب في غيرها. فتُقرأ إلى
`court_case_number`، و«الجهة المختصة» (أو «الجهة» أو «المحكمة») إلى
`authority`، **بلا تفرّد** وفي الدمج كبقية الحقول.

وكان رقمُ الجهة هو المفتاح: مشروعان لقضيةٍ واحدةٍ عند المحكمة يسقط ثانيهما
«مكرّراً»، ومشروعٌ بلا رقمٍ يُولَّد له رقم، ورقمٌ تبدّل في الملفّ يفتح
اختلافاً. وكلُّه زال. وخريطةٌ محفوظة قديمة تُحوَّل عند قراءتها: «رقم القضية»
يصير رقمَ الجهة، و«رقم المشروع»/«رقم الملف» يظهران «بلا ربط».

**وإعادةُ الاستيراد من الصفر** (أسفل شاشة الربط، للمسؤول): نسخةٌ احتياطية ←
معاينةٌ بالأعداد ← عبارةُ التأكيد «أعد الاستيراد». تحذف القضايا التي ربطها
مشروعٌ ومعها دفعاتُها وعمولاتُها وما أُضيف عليها، وتُرجع دفعاتِ وافق «بلا
قضية»، وتفكّ ربطَ المشاريع **مع إبقاء تصنيفها**؛ ويبقى العملاءُ والقضايا
اليدوية. ثمّ «معاينة» و«مزامنة» كالمعتاد. والنشرُ لا يحذف شيئاً — والقضايا
المربوطة التي لم يُعَد استيرادُها تُرقَّم برقم مشروعها في المزامنة التالية.

**والحقول المقروءة**: اسمُ العميل (أو اسمُ الشركة) ورقمُ هويته ونوعُها
وجوّالُه وبريدُه و**نوعُ العميل** وسجلُّه التجاري و**مسؤولُ التواصل**
و**ملاحظاتُه**؛ ونوعُ المشروع وموضوعُه وحالتُه و**نتيجتُه** و**ملاحظاتُه**،
و**الجهةُ المختصة ورقمُ القضية لديها**.

و«مسؤول التواصل: أحمد الغامدي - 0551234567» سطرٌ فيه ثلاثة: اسمٌ ورقمٌ
وربما هوية — تُقرأ إلى `legal_representative`، ولا يُحشر السطرُ كلُّه في
خانة الاسم.

و**الملاحظاتُ تُقرأ ولو كانت أسطراً تحت عنوانها**:

```
الملاحظات:
- العميل يفضّل التواصل مساءً
- الأوراق الأصلية عند وكيله
```

فعنوانٌ تُرك فارغاً يأخذ ما تحته حتى العنوان التالي. وعنوانٌ حمل قيمةً لا
يأخذ ما بعده — وإلا دخل ذيلُ الملفّ في حقلِ موكّل كأنه منه.

وعنوانٌ في الملفّ بلا مقابلٍ في الخريطة **يُعرض في المعاينة** — فلا يضيع
حقلٌ صامتاً لأنّ أحداً لم يعرف أنه هناك.

### المراجعة الدورية — ولا يقف عليها استيراد

**المعاينةُ بوّابةٌ لمرّةٍ واحدة، لا في كل دورة.** تُشغَّل قبل فتح الجدولة
ليرى صاحبُ المكتب ما ستكتبه، ثمّ تعمل الجدولةُ كلَّ ساعة بلا أحد: تمسح،
وتزامن، وتكتب.

لكنّ المزامنة تُنتج في طريقها أشياءَ تستحقّ نظراً — نوعٌ اقترحه الطراز،
ولفظٌ لم يُفهم، ومشروعٌ جديد صُنّف آلياً، واسمٌ يشبه
اسماً. وكانت هذه **تنبيهاتٍ في ناتج المعاينة**: يراها من شغّل معاينةً،
وتتبخّر مع الدورة. فمن يعتمد على الجدولة لا يراها، ومن يريد أن يراها
يُشغّل معاينةً في كل مرّة — وهو التطويلُ بعينه.

فصارت صفوفاً في لوح **«يستحقّ نظرك»**، تكتبها المزامنةُ وتمضي:

| السؤال | ما يُحسم به | وأين يثبت |
|---|---|---|
| تصنيفُ مشروعٍ جديد | «مشروعُ عميل» أو «إداريٌّ داخلي» | `decided_by` — ولا ينقضه مسحٌ لاحق |
| لفظٌ لم يُفهم | تختار ما يقابله من القائمة | يُكتب في العمود **ويُحفظ في المعجم** |
| نوعٌ اقترحه الطراز | «صحيح» أو تختار غيره | عمودُ نوع القضية |
| عميلٌ يشبه عميلاً | «هما واحد» فيُدمجان، أو «مختلفان» | القضايا تنتقل، والمكرَّر يُؤرشف |

**ولا يعود سؤالٌ حُسم.** الصفُّ فريدٌ بـ(المشروع + نوع السؤال + القيمة
المسؤول عنها) — فمزامنةُ كلِّ ساعة على الحال نفسِه لا تفتح نسخةً ثانية،
ولا تُعيد ما حُسم بالأمس. ولا يُفتح ثانيةً إلا إذا تبدّل ما سُئل عنه،
وحينها هو سؤالٌ آخرُ بحقّ.

**والاستيرادُ لا ينتظره.** القضيةُ كُتبت والعميلُ كُتب قبل أن يُفتح الصفّ.
فمكتبٌ لا يفتح الشاشة شهراً تبقى استيراداتُه جارية، وتنتظره أسئلتُه
مجموعةً حين يفتحها.

### المزامنة المستمرّة والدمج الثلاثي

تعمل كلَّ ساعة (`[triggers]` في `wrangler.toml`)، ولا تُفتح إلا بعد تنفيذٍ
يدويٍّ ناجح. تلتقط المشروع الجديد فتصير قضيةً في المنصة، وتحدّث ما تبدّل.

ولكل حقلٍ ثلاثُ قيم: ما في المنصة الآن، وما كتبته المزامنة آخرَ مرّة، وما في
بيسكامب الآن. ومنها يُعرف من تحرّك:

| المنصة | بيسكامب | العمل |
|---|---|---|
| كما تركناها | تبدّل | **يُكتب** بلا إزعاج |
| كما تركناها | كما هو | لا شيء |
| مسّتها يد | كما هو | يُترك — المنصة أحدث |
| مسّتها يد | تبدّل | **تبقى قيمةُ المنصة** — أو تقف اختلافاً إن اختير «اسألني» |

**فما عُدِّل في المنصة هو المعتمد وإن خالف بيسكامب.** تصحيحٌ كتبه المحامي لا
يُمحى صامتاً، والحقلُ الذي لم تمسّه يدٌ يبقى يتحدّث من بيسكامب.

**والتعارضُ لا يوقف استيراداً**: هو حقلٌ واحد لا يُكتب، وبقيةُ الحقول
والقضايا والعملاء تُكتب كلُّها. ومن استقرّ عنده أيُّ الطرفين أصحّ يضبط
**سياسةَ الاختلاف** مرّةً فلا يحسم حقلاً حقلاً:

| السياسة | ما يقع |
|---|---|
| «أبقِ ما في المنصة» — الافتراض | تبقى قيمتُك، وتُثبَّت الصورة فلا يُسأل عنها ثانيةً |
| «اسألني» | يُسجَّل بالقيمتين وينتظر قرارك: «خذ من بيسكامب» أو «أبقِ ما في المنصة» أو «تجاهل» |
| «خذ من بيسكامب» | تُكتب قيمتُهم، وما تكتبه في المنصة يُدهس في الدورة التالية |

**والعميلُ يُدمَج كقضيته.** كان يُكتب مرّةً عند إنشائه ثم لا يُعاد إليه —
فمكتبٌ يضيف اليوم «نوع العميل» و«الملاحظات» إلى ملفّات موكّليه القدامى
يزامن فلا يقع شيء. وصار حقلُه يُدمج بالجدول أعلاه، بفارقٍ واحد في أوّل
لقاء: العميلُ قد يكون كُتب في المنصة قبل بيسكامب بسنة، فما كان فارغاً
يُملأ صامتاً، وما فيه قيمةٌ تخالف **يقف اختلافاً ينتظر قرارك** — لا يُدهس
ولا يُهمَل. و«فرد» في نوع العميل تُعدّ فراغاً: هي افتراضُ العمود لا قرارَ
أحد.

**والحقول التي لا تمسّها المزامنة أصلاً**: الأتعاب والعمولات والمسوّق — ليست
في «بيانات المشروع»، وتُدار في المنصة وحدها.

### لوحةُ العملاء المحتملين — في الاتّجاهين

مشروعٌ واحد في بيسكامب (مثل «إدارة العملاء») فيه لوحةُ بطاقات (Card Table):
كلُّ حالةٍ في «تكوين النظام» عمود، وكلُّ عميلٍ محتمل بطاقة. ويُضبط من
`الإعدادات ← الربط ببيسكامب ← لوحة العملاء المحتملين` بمعرّف المشروع أو رابطه
— لا في الشيفرة. والإعدادُ يطابق الأعمدةَ بالحالات بالاسم، وينشئ الناقصَ منها
ومعها عمودُ «تحوّل إلى عميل»، ويسجّل Webhook على المشروع. وتُعاد بعد إضافة
حالةٍ جديدة في «تكوين النظام».

| ما يقع | أثرُه |
|---|---|
| عميلٌ يُنشأ أو يُعدَّل في المنصة | تُنشأ بطاقتُه أو يُحدَّث وصفُها، في عمود حالته |
| سحبُ البطاقة في لوحة المنصة أو في بيسكامب | تتبدّل الحالة في الطرف الآخر |
| بطاقةٌ تُنشأ في بيسكامب | عميلٌ محتملٌ جديد. وصفٌ بالصيغة يُقرأ بالقاعدة، ونصٌّ حرٌّ يُحفظ ملاحظةً ويُستخرج منه وتعليقاتِه الجوّالُ والبريدُ ونوعُ العميل وغيرُها آلياً |
| تعليقٌ في أحد الطرفين | يُنسخ في الآخر مرّةً واحدة، ويملأ ما فرغ من الملفّ إن حمل بياناً |
| التحويلُ إلى عميل | تنتقل البطاقة إلى «تحوّل إلى عميل»، ويحفظ العميلُ رقمَها |
| الحذفُ في أحد الطرفين | لا يحذف في الآخر. ومن حُذف في المنصة لا تُعيده بطاقتُه |

**الحالاتُ الافتراضية** (وتُحرَّر من «تكوين النظام»): جديد ← تم التواصل ←
استشارة مجدولة ← تم إرسال عرض السعر ← بانتظار توقيع، والإغلاق: لا يرد / متوقف ·
اعتذرنا عنه · رفض العميل. وما في «حالات الإغلاق» لا يُعدّ «قيد المتابعة»، وآخرُ
حالةٍ مفتوحة هي «الجاهزة للتحويل». والأسماءُ القديمة نُقلت في `migrations/0030`
(مهتم ← تم التواصل، غير مناسب ← اعتذرنا عنه، تم الرفض ← رفض العميل) ما لم يكن
المكتبُ قد حرّر قائمته. وعمودٌ في بيسكامب باسمٍ قديم يُعاد تسميتُه عند الإعداد،
أو — إن كان للجديد عمود — يُترك وتُنقل بطاقاتُه منه.

**صيغةُ الوصف**: العنوانُ اسمُ العميل، ثم أسطرُ «الحقل: القيمة» (رقم الجوال،
البريد الإلكتروني، نوع العميل، نوع الهوية، رقم الهوية، السجل التجاري، المصدر،
القيمة المتوقعة، موعد المتابعة)، ثم «الملاحظات:» وما بعدها كلُّه ملاحظة.

**الدمجُ ثلاثيّ** على صورةٍ محفوظة (`prospects.bc_synced_values`): ما تبدّل
في طرفٍ وحده يُنقل، وما تبدّل في الطرفين معاً يُعرض في «اختلافاتٌ تنتظر قرارك»
ولا يُكتب. **والاستخراجُ الآليّ** لا يملأ إلا الفارغ، ولا يقبل قيمةً لا تظهر
في نصّ البطاقة أو تعليقاتها حرفاً.

والإشعارُ الفوريّ يصل `POST /api/basecamp/prospects/webhook/<سرّ>` — يسبق
الحارس، وحراستُه سرٌّ في المسار، ولا يُوثَق بجسمه: يُؤخذ منه رقمُ البطاقة
ويُقرأ حالُها من الواجهة. والمطابقةُ الكاملة تجري كلَّ ساعة احتياطاً.

### آخرُ ما حدث في بيسكامب — في نافذة القضية

قضيةٌ مربوطةٌ بمشروع تعرض في نافذتها أحدثَ عشرين حدثاً منه: مهامُّ (ومنجزةٌ
منها)، وتعليقاتٌ، ورسائلُ، وملفّات — بالكاتب والتاريخ ورابطِ كلٍّ (`GET
/api/cases/:id/timeline`، `worker/lib/basecamp/timeline.js`). **قراءةٌ لا
كتابة** كبقية الربط، وتُخبَّأ عشرَ دقائق فلا يستهلك فتحُ النوافذ حدَّ النداءات
الذي تحتاجه المزامنة. ونوعٌ سقطت قراءتُه لا يُسقط الباقي ويُقال.

### هويّةُ الموكّل — واحدٌ وإن اختُلف رسمُ اسمه

«محمد خالد عبدالله القحطاني» و«محمد خالد القحطاني»: **رقمُ الهوية هو
الفصل**. إذا اتّحد فهو موكّلٌ واحد مهما اختلف رسمُ الاسم — ولا يُنشأ له
ملفٌّ ثانٍ، ولا يقف اسمُه اختلافاً في كل مزامنة. ويُكتب الأتمُّ من
الاسمين: هو ما يُكتب في الوكالة والصحيفة.

والمقارنةُ تُسقط ما لا يفرّق: أداةَ التعريف («القحطاني» و«قحطاني»)،
و«بن»، ورسمَ «عبد الله» و«عبدالله».

**وبلا رقم هوية يُقترح ولا يُدمج.** «محمد القحطاني» اسمُ عشرة، ودمجُ
ملفَّي موكّلين مختلفين خطأٌ لا يُكشف إلا بعد أن يُبنى عليه — توكيلٌ في
ملفّ غيره، وقضيةٌ تُنسب إلى من ليس صاحبَها. فتقول المعاينة «يشبه عميلاً
قائماً: فلان — راجِعه»، ويبقى الحكمُ لمن يقرأ.

ويُميَّز الأخُ من أخيه والابنُ من أبيه: الاحتواءُ لا يكفي، بل يلزم اتّحادُ
الاسم الأول والأخير معاً — فـ«خالد عبدالله القحطاني» ليس اختصاراً لـ«محمد
خالد عبدالله القحطاني».

### التلخيصُ الآليّ عند الاستيراد

يعمل من أوّل نشرة، ويُطفأ من الشاشة. وهو ثلاثة أشياء:

- **ملخّصُ كلّ قضية** — سطرٌ يُكتب في حقل `ai_summary`.
- **ملخّصُ قضايا كلّ موكّل** — «ثلاثُ قضايا تجارية، اثنتان مكتملتان»،
  يُبنى من صفوف قضاياه في المنصة لا من ملفٍّ واحد.
- **اقتراحُ نوع القضية** حين يخلو منه الملفّ — **من قائمة «تكوين النظام»
  وحدها**. فما ردَّه الطراز خارجَها يُردّ، وأسوأُ ما يقع أن يبقى الحقل
  «غير محدّد» كما كان. ويُعلَّم في المعاينة «مقترَح» ليُراجَع.

**وفي حقلٍ مستقلٍّ عن الملاحظات**، مسمّىً «ملخّصٌ آليّ» في نافذة القضية
والعميل. فالملاحظاتُ يكتبها المحامي ويأتي فيها ما في «بيانات المشروع»،
ونصٌّ آليٌّ لو دخلها لاختلط بما كتبه إنسان — فيُقرأ بعد شهرٍ كأنه منه،
ويدخل الدمجَ الثلاثي فيبدو أنّ «يداً مسّت الحقل» في كل دورة.

**ولا يُخترع حقل.** الطراز يُلخّص ما أُعطي ويصنّف من قائمةٍ مغلقة — ولا
يملأ اسماً ولا رقماً ولا تاريخاً. تلك تُقرأ بقاعدةٍ تُخطئ خطأً ظاهراً أو
تصيب، لا بترجيحٍ يُنتج قيمةً معقولة لم تُكتب قطّ.

#### والقراءةُ الآلية حين يتبدّل شكلُ الملفّ

القارئُ قواعدُ عمداً — «اسم العميل: …» يُقرأ بقاعدةٍ تُخطئ خطأً ظاهراً أو
تصيب. لكنّ ذلك يفترض أنّ شكل الملفّ ثابت، وهو ليس كذلك: عنوانُه تبدّل
مرّةً، وبنودُه تتبدّل، وكاتبٌ يكتب فقرةً حيث كان غيرُه يكتب حقولاً. وحين
لا تجد القاعدةُ عنواناً كان المشروعُ كلُّه يُردّ `no_client_name` — وفيه
اسمُ الموكّل مكتوبٌ في سطره الأول.

**فالفراغُ ليس أسلمَ من التخمين دائماً؛ هو أسلمُ من تخمينٍ يُكتب صامتاً.**

فالطراز يقرأ، والقواعدُ تحكم — بأربعة شروطٍ كلُّها لازم:

1. **لا يُنادى إلا حين تعجز القاعدة.** ما قرأته الخريطةُ سيّدٌ لا يُنقَض.
   والشرطُ أن يدلّ الظاهرُ على العجز: لا اسمَ عميل، أو لا سطرَ معنونٌ
   واحد، أو حقولٌ فارغةٌ **ومعها عناوينُ بلا ربط**. وملفٌّ تامُّ الشكل لا
   يُستدلّ عليه أصلاً.
2. **كلُّ قيمةٍ تُطابَق بالملفّ حرفاً.** ما لا يظهر في نصّ المستند يُطرح
   مهما بدا معقولاً — وهذا هو الحدُّ الذي يفصل النقلَ عن التأليف. (والرقمُ
   يُقارن أرقاماً مجرّدة: «+966 55 …» و«055…» واحد.)
3. **ثم تمرّ على المدقّقين أنفسِهم** — `normalizePhone` للجوّال،
   و`normalizeIdNumber` للهوية، وجدولِ المفردات لـ«منظورة» و«منجزة» —
   كما لو جاءت من عنوانٍ معروف. فطريقا القراءة ينتهيان إلى التوحيد نفسه.
4. **ولا يُدهس شيء.** يُملأ الفارغُ وحده، ويُعرض كلُّ حقلٍ جاء من هنا في
   المعاينة: «قرأها الطراز: اسم العميل، حالة المشروع — راجِعها».

**ورقمُ القضية خارجَ ذلك بقصد.** هو مفتاحُ الربط: تُطابَق به القضيةُ
القائمة ثم يُكتب فيها. وملفُّ مشروعٍ قد يذكر رقمَ قضيةٍ أخرى — قضيةٍ
مرتبطة أو حكمٍ سابق — فينقله الطراز نقلاً صحيحاً من النصّ، فيُربط المشروعُ
بقضية موكّلٍ آخر وتُكتب حقولُه فيها. فالنقلُ الحرفيّ يمنع الاختراع ولا
يمنع أخذَ الرقم الخطأ. والبديلُ رقمٌ مولَّدٌ يُعلَّم «يحتاج تصحيحاً» — وهو
ظاهرٌ يُصحَّح، لا ربطٌ صامتٌ بملفّ غيره.

وأسوأُ ما يقع بعد هذه الشروط: قيمةٌ صحيحةُ الشكل منقولةٌ من الملفّ وُضعت
في الحقل الخطأ — تُرى في المعاينة قبل أن تُكتب.

#### واقتراحُ ربطٍ للبنود الجديدة

بندٌ يُضاف إلى الملفّ يظهر في المعاينة «بلا ربط»، ويُترك ربطُه لمن يفتح
الشاشة — وهو عملٌ يُؤجَّل فتضيع الحقول ما دام أُجِّل.

فزرُّ **«اقترح ربطاً من ملفّاتي»** في شاشة الخريطة: يقرأ ثلاثةَ ملفّاتٍ
حقيقية، ويجمع عناوينَها التي لا ربط لها، ويقترح لكلٍّ حقلَه — من قائمة
حقول المنصة حرفاً، وما لا يقابله حقلٌ يُترك.

**ولا يُحفظ شيء**: الاقتراحاتُ صفوفٌ تُضاف مسوَّدةً، تُراجَع ثم تُحفظ
بضغطة صاحبها. خطأٌ واحد في الخريطة يتكرّر على الحساب كلِّه، وذلك قرارٌ لا
يُترك لاستدلال.

#### ما يخرج إلى الطراز

| يخرج | لا يخرج |
|---|---|
| اسمُ الموكّل ونوعُه | رقمُ الهوية |
| نوعُ القضية وموضوعُها وحالتُها ونتيجتُها | الجوّال والبريد |
| ملاحظاتُ القضية | الأتعابُ والعمولات |

وفي القراءة الآلية وحدها يخرج **نصُّ الملفّ** — لأنّ المطلوب قراءتُه، ولا
يُقرأ ما لا يُمرَّر. ولا تقع إلا على ملفٍّ عجزت عنه القاعدة.

والاستدلال على **Claude** (Haiku للقراءة والتصنيف، Sonnet للصياغة) متى ضُبط
`ANTHROPIC_API_KEY`، وإلا على **Workers AI** — انظر «الطراز» أعلاه.

#### وصياغةُ العنوان والموضوع

«موضوع القضية» إلزاميّ، وما يُستورد منه خامٌ من الملفّ. فيصوغ Sonnet بعد كل
مزامنة (٢٠ قضيةً، والمنتهيةُ أوّلاً) **عنواناً قصيراً** (`cases.title`) و**موضوعاً
بالفصحى**، والأصلُ يُحفظ في `summary_raw` ويُعرض في نافذة القضية «الموضوع كما
ورد». **وما عدّله إنسانٌ لا يُمسّ**: الحقلُ للطراز ما دام فارغاً أو خاماً أو هو
ما صاغه (`ai_summary_text`/`ai_title`)؛ وتبدّلُ الموضوع في بيسكامب يصل ثمّ يُعاد
صياغتُه. و«صُغ القضايا الآن» في شاشة الربط يصوغ ٣٠ في الضغطة، و«صُغ بالذكاء
الاصطناعي» في نافذة القضية يصوغ قضيةً واحدة — ولو كتبها إنسان، بطلبه.

#### والموضوعُ المقترح لقضيةٍ بلا موضوع

القضايا المنتهية خاصّةً لا يحمل ملفُّها «موضوع المشروع». فيصوغ Sonnet موضوعاً
مختصراً من نصّ الملفّ وأحدث نشاط المشروع (مهامّ ورسائل وتعليقات)، **ويُكتب في
الحقل الفارغ وحده** ويُفتح له سؤالٌ في «يستحقّ نظرك» ليُؤكَّد أو يُعدَّل.
والنتيجةُ تُكتب كذلك إن نُصّ عليها صراحةً وكانت فارغة. والمنتهيةُ أوّلاً،
بسقفٍ مستقلّ (١٥ في الدورة)، وبصمةٌ على نصّ الملفّ تمنع إعادةَ السؤال.
والأرقامُ الطويلة (هويةٌ أو جوّال) تُقصّ من النصّ قبل أن يخرج.

#### والنتيجةُ تحت عنوان الحالة

«حالة القضية: ربحانة» تُقرأ **حالةً مكتملةً ونتيجةً ربحاً**، و«خسرانة» خسارة،
و«صلح» تسوية، و«منتهية لصالحنا» الاثنين معاً — بالجذور وبحارس النفي نفسِه
(«لم نربح» لا تُقرأ ربحاً). ونتيجةٌ لها عنوانُها في الملفّ لا يمحوها ما قُرئ من
عنوان الحالة.

وهذا أوسعُ ممّا يخرج إلى استبصارات التحليلات — تلك أرقامٌ مجمَّعة وحدها،
بلا اسمٍ ولا نصّ، ولم يتغيّر ذلك.

#### والاستدلالُ لا يتكرّر ولا يُسقط شيئاً

تُحفظ بصمةُ النصّ الذي لُخِّص: ما دام هو هو فالملخّصُ هو هو، فلا تدفع
مزامنةُ كلِّ ساعةٍ ثمنَ تلخيصٍ مكرّر. وللدورة سقفٌ (٢٥ استدلالاً)، وما
زاد يُلخَّص في التي تليها ويُقال عددُه — فلا يُظنّ أنّ الميزة عطلت.

وسقوطُ الاستدلال لا يُسقط الاستيراد: تُكتب القضيةُ بلا ملخّص، ولا تُثبَّت
بصمةٌ على سقوطٍ — فتُعاد المحاولةُ في الدورة القادمة.

**والبصمةُ على المعنى لا على الحروف.** محامٍ يفتح الملفّ فيصلح مسافةً، أو
يضع فاصلةً، أو يشكّل حرفاً، أو يكتب «إجراءات» بعد «اجراءات» — فتتبدّل
الحروفُ ولا يتبدّل المعنى، وبصمةٌ حرفيةٌ تُعيد تلخيصَ الملفّ كلِّه لأجل
مسافةٍ وتُنتج النصَّ نفسَه. فتُرفع الحركاتُ والتطويل، وتُوحَّد صورُ الألف
والياء والتاء المربوطة، وتُطرح علاماتُ الترقيم — وما بقي بعد ذلك **تبدُّلٌ
في الكلام نفسِه**، وهو وحده يستحقّ صياغةً جديدة.

### ألفاظُ النتيجة والحالة كما تُكتب

تعديلُ «بيانات المشروع» تلتقطه المزامنةُ الآلية في الدورة التالية: تمسح
ثم تزامن، فيصل تفصيلٌ أُضيف ونوعُ قضيةٍ بُدّل ونتيجةٌ كُتبت. وبالدمج
الثلاثي: ما لم تمسّه يدٌ في المنصة يُكتب بلا إزعاج، وما مسّته يقف اختلافاً.

**لكنّ اللفظ يجب أن يُفهَم.** و`outcome` و`status` و`client_type` أعمدةٌ
مغلقة تقرؤها اللوحةُ والتقارير رموزاً — «معدّل الربح» يعدّ
`outcome = 'won'` وحدها. فلفظٌ حرٌّ يُكتب فيها يظهر في بطاقة القضية
**ويغيب عن كل إحصاء**.

فثلاثُ طبقات:

1. **جدولُ المفردات** — «رابحة» و«لصالحنا» و«حكم لنا».
2. **الجذر** — «ربح» و«خسر» و«صلح». وبه تُفهم «ربحانة» و«ربحناها»
   و«خسرناه» و«كسبناها»، وهي صيغٌ لا تنتهي فلا يلحق بها جدول. **والنفيُ
   يُبطله**: «لم نربح» فيها «ربح» ومعناها ضدُّه، فتُردّ غيرَ مفهومة.
3. **الطراز** — يردّ ما بقي إلى رمزٍ من القائمة المغلقة حرفاً، ويُقال في
   المعاينة: «"طلعت لنا" فُهمت النتيجة: رابحة — راجِعها».

   **واللفظُ يُقرأ في سياقه**: تُمرَّر معه ملاحظاتُ القضية وموضوعُها. فـ
   «تحت الدراسة» وحدَها لا تقول شيئاً، وفي الملاحظات «صدر الحكم لصالحنا
   وننتظر التنفيذ» ما يفسّرها. والسياقُ عونٌ على فهم اللفظ لا بديلٌ عنه.

   **وما فُهم مرّةً يُحفظ**: معجمٌ في `system_settings` يُقرأ ويُصحَّح.
   واللفظُ يبقى في الملفّ حتى يعدّله إنسان، والمزامنةُ كلَّ ساعة — فبلا
   ذاكرةٍ يُستدلّ على اللفظ نفسِه أربعاً وعشرين مرّةً في اليوم بالجواب
   نفسِه. **ولا يُخفي المعجمُ شيئاً**: المعاينة تقول «فُهمت — راجِعها» في
   كل دورة، جاء الجوابُ منه أو من الطراز.

**وما لم يُفهَم لا يُكتب**، ويُقال: «لفظٌ لم يُفهم في النتيجة: "تحت
الدراسة" — لم يُكتب». فالحقلُ يبقى كما كان ظاهراً في المعاينة، ولا يدخل
العمودَ نصٌّ يكسر الإحصاء صامتاً.

و**نوع القضية** ليس منها: قائمتُه في «تكوين النظام» مفتوحة، يكتب فيها
المكتب ما شاء — فيُكتب اللفظُ كما هو.

### ما يقع للأرقام الناقصة

ملفٌّ بلا رقم هوية أو بلا رقم قضية لا تُسقَط قضيتُه: يُولَّد رقمٌ **ثابت**
مشتقٌّ من معرّف المشروع (فمزامنةٌ ثانية تجد الصفَّ ولا تُنشئ ثانياً)،
ويُعلَّم في المعاينة «يحتاج تصحيحاً». والملفُّ بلا اسمِ عميلٍ يُردّ بسببٍ
مسمّى ولا يُكتب منه شيء.

ومشروعان لعميلٍ واحد → **عميلٌ واحد وقضيتان**، لكلٍّ رابطُ مشروعها. وهو
عينُ ما تعرضه شاشةُ العميل أصلاً.

### كلُّ تحديثٍ مربوطٌ بمعرّف المشروع

القضيةُ التي ربطها مشروعٌ مرّةً هي قضيتُه أبداً — بمعرّفه عند بيسكامب، وهو
لا يتبدّل. فيتبدّل «رقم المشروع» في الملفّ فتتبدّل القضيةُ نفسُها، ولا
يُنشأ غيرُها. ورقمُ المشروع لا يُطابَق به إلا مشروعٌ لم يُربط بعد.

ومشروعٌ يحمل رقمَ قضيةٍ يربطها مشروعٌ آخر — ملفٌّ نُسخ من ملفّ، أو خطأٌ في
الكتابة — **لا يُكتب فيها**: يُردّ `case_number_taken` ويُسمّى في المعاينة.
ورقمٌ جديد في ملفّ مشروعٍ مربوط يطابق قضيةً أخرى يبقى معه الرقمُ القائم
ويُقال.

وسجلُّ المزامنة في شاشة الأنشطة يسمّي كلَّ مشروعٍ كتب وقضيتَه وما أنشأه وما حدّثه.

### المشروعُ المؤرشف منتهٍ

أرشفةُ المشروع في بيسكامب إعلانُ أنّ العمل انتهى، وإن بقي في الملفّ «قيد
المعالجة». فحالةُ قضيته **«مكتملة»**، وتبقى ظاهرةً في القوائم والإحصاءات —
لا تُؤرشف في المنصة. وتمرّ على الدمج كقيمةٍ من بيسكامب: حالةٌ عدّلتها يدٌ
في المنصة تبقى.

## ما لم يُبنَ بعد

يُذكر هنا صراحةً كي لا تُقرأ شاشةٌ على أنها تعمل:

- **المساعد الذكي** — لا شاشةَ له: «المحامي الذكي» حُذف وخدمتُه في منصةٍ
  أخرى من منصات ناف. و`src/services/geminiService.ts` يبقى وثيقةَ قرارٍ لمن
  يربط مساعداً لاحقاً — النداء من الـWorker ومفتاحُه سرٌّ هناك، لا `VITE_*`
  في حزمة المتصفّح.
- **مصدرُ بياناتٍ مركَّب في التقارير** (`mixed`) — الوصلُ بين جدولين.

## سجلُّ الأنشطة

يكتبه الخادمُ من موضعٍ واحد — `worker/lib/activity.js` يناديه `crud.js` —
فيمرّ به كلُّ إنشاءٍ وتعديلٍ وحذفٍ وفعلٍ جماعيّ على العملاء والمحتملين
والقضايا والمسوّقين والعمولات، ومعه تحويلُ المحتمل ومزامنةُ بيسكامب.

والنوعُ `‎<كيان>_<فعل>‎`، والفاعلُ من الجلسة لا من الجسم، واسمُه نصٌّ محفوظ
وقتَ الفعل فيبقى صادقاً بعد تغيّره. وأثرٌ تعذّر تسجيلُه لا يُسقط العملية
التي وقعت.

## دفعاتُ العمولة

تُسجَّل من «تفاصيل المسوّق»: قضيةٌ ومبلغٌ بالريال وتاريخٌ وملاحظة. والمدفوعُ
لكلِّ قضية يُجمع من الدفعات نفسها، و«المتبقّي» فرقُ المستحقّ عنه — ولا حقلَ
في صفّ القضية يحمل أيّاً منهما.

## دفعاتُ العميل وكشفُ الحساب

«المبلغ المحصَّل» لم يعد رقماً يُكتب بيد: **هو مجموعُ سجلّ الدفعات**
(`client_payments`، هجرة `0018`). لكل دفعةٍ مبلغُها وتاريخُها وطريقتُها ومرجعُها،
وتُسجَّل من نافذة القضية.

والمجموعُ يحسبه الخادم في `worker/lib/payments.js` وحدَه، ويكتبه في
`payment_status` نفسِه بعد كل دفعةٍ تُضاف أو تُحذف وبعد كل حفظٍ للقضية — فيبقى
كلُّ من يقرأ ذلك العمود صحيحاً بلا تعديل: إحصاءاتُ المسوّق وجدولُ قضاياه
والتقارير. ومحصَّلٌ ترسله الشاشة يُطمس بمجموع السجلّ.

- **الدفعةُ لا تُعدَّل**: تُحذف وتُكتب صحيحة، فيبقى ما وقع ظاهراً. ولا حذفَ جملةً.
- **موكّلُها من القضية** لا من الجسم الوارد، و**مصدرُها** يكتبه الخادم.
- **الرصيدُ الافتتاحيّ**: كلُّ محصَّلٍ كان مكتوباً قبل السجلّ صار دفعةً واحدة
  بالمبلغ نفسِه (`source = 'opening'`) — فلم يتبدّل رقمٌ في أيّ شاشة.
- **كشفُ الحساب** في تفاصيل العميل: أتعابُ كلِّ قضيةٍ ومحصَّلُها ومتبقّيها،
  والدفعاتُ بتاريخها، وتصديرُه Excel.
- **«مستحقّات غير محصّلة»** بطاقةٌ في اللوحة — **ولا تبلغ شاشات العرض**: تلك
  أعدادٌ ونسبٌ وحدها، و`readStats(env, { publicBoard: true })` لا يحسب المبلغ لها أصلاً.

## الربطُ بوافق — المدفوعاتُ إلى قضاياها

`الإعدادات ← الربط بوافق`. **يُقرأ من وافق ولا يُكتب فيه**، كبيسكامب. وتلزمه
سرٌّ واحد:

```bash
wrangler secret put WAFEQ_API_KEY
```

أو من لوحة Cloudflare نوعَ **Secret**. وغيابُه غيابُ الربط: الشاشة تقول «لم
يُضبط المفتاح» ولا يُقرأ شيء.

**والدفعةُ في وافق تخصّ موكّلاً ولا تقول أيَّ قضيةٍ له.** فتُحفظ أوّلاً في
`wafeq_payments` بحالتها، **ولا تنزل إلى سجلّ الدفعات إلا ما رُبط** — فلا
يتحرّك المحصَّل بترجيح. والربطُ ثلاثُ طبقات، الأوثقُ أوّلاً:

| الطبقة | ما يقع |
|---|---|
| **مشروعُ وافق مربوطٌ من قبل** (بتطابق الاسم أو بتأكيدك) | **يُربط آلياً** |
| رقمُ المشروع أو رقمُ القضية لدى الجهة حرفاً في المرجع أو الوصف أو الفاتورة (وقضيةٌ واحدةٌ تطابقه) | **يُربط آلياً** |
| **اسمُ مشروع وافق = اسمُ مشروع بيسكامب** بعد التوحيد، وقضيةٌ واحدة | **يُربط آلياً، ويُتذكَّر المشروع** |
| اسمُ مشروع وافق **يشبه** مشروعاً واحداً بوضوح | يُقترح — وإن تقارب اثنان سُئل الطرازُ بينهما وحدهما |
| الدافعُ موكّلٌ معروف (سجلّه أو هويته أو اسمه) | يحصر المرشّحين في قضاياه، ويُقترح إن كانت واحدة |
| الطراز (Claude Haiku، أو Workers AI) | يختار من **قائمةٍ مغلقة** أو يقول «لا أعرف» — ويُقترح بسببه |

والمقترَحُ ينتظر في لوح **«مقترَحة»** حتى تؤكّده بضغطة، أو تختار غيره، أو
تتجاهله. وما حسمه إنسانٌ لا تنقضه دورة، وتبدُّلُ مبلغِ دفعةٍ مربوطة عند وافق
يُنقل إلى السجلّ. ودفعةُ وافق لا تُحذف من نافذة القضية — تُصحَّح هناك.

**ما يخرج إلى الطراز**: نصُّ الدفعة وفواتيرها واسمُ الدافع، ورقمُ القضية
ونوعُها وموضوعُها واسمُ موكّلها ومتبقّيها — لا رقمَ هويةٍ ولا جوّال. ولا يُسأل
عن النصّ نفسِه مرّتين (بصمة)، وسقفُ وافق ٦٠ سؤالاً في الدورة (مستقلٌّ عن
بيسكامب).

**وإيرادٌ عامّ بلا قضية**: عمليةٌ سريعة لا قضيةَ لها تُسجَّل «إيراداً عامّاً»
(حالة `general`) بموكّلها إن عُرف — فتظهر في كشف حسابه، وتُجمع في بطاقة
«المحصَّل هذا العام» في لوحة التحكم بجانب دفعات القضايا. ولا تنزل إلى
`client_payments` (سجلُّ القضايا)، ولا تنقضها مزامنة.

**ومشروعُ وافق هو المفتاحُ الأوّل.** المدفوعاتُ مربوطةٌ بفواتير لها مشروع،
واسمُه في الغالب اسمُ مشروع بيسكامب — أي القضية — أو قريبٌ منه؛ أمّا الدافعُ
فقد يكون شركةً تابعة أو قريباً للموكّل. فيُوحَّد الاسمان وتُطرح الألفاظُ
المتكرّرة («قضية»، «مشروع»، «أتعاب») و«ال»، ثمّ يُقاس اشتراكُ الكلمات. ومشروعُ
الفاتورة يُؤخذ حين لا تحمل الدفعةُ مشروعاً. **وكلُّ تأكيدٍ يُعلّم المنصة**:
يُحفظ ربطُ المشروع بقضيته (`wafeq_project_links`)، وتُربط دفعاتُه المعلّقة في
الحال والتاليةُ آلياً. ولوحُ «مشاريع وافق المربوطة» يعرضها ويفكّها.

**والدفعةُ عند وافق لا تحمل وصفاً** — فيها `reference` و`project` ومعرّفُ
الجهة ومعرّفاتُ الفواتير (`invoice_payments[].invoice`). فتفصيلُ العمل يُقرأ من
**الفاتورة بمعرّفها**: رقمُها ومرجعُها وملاحظاتُها وشروطُها ووصفُ كلّ بند،
وجهتُها إن غابت عن الدفعة. واسمُ **المشروع** عند وافق يُقرأ بمعرّفه كذلك (قد
يكون اسمَ القضية). وسقوطُ قراءة فاتورةٍ يُعدّ في الحصيلة، ومعرّفاتُها تُحفظ
فيعيد قراءتَها زرُّ «اربط بالذكاء الاصطناعي الآن». وتحت كلّ دفعة سطرُ **«ما
قُرئ»**، و«اختبار الاتصال» يعرض أسماءَ حقول الفاتورة والجهة أيضاً — لا قيمَها.

**والجهةُ تأتي معرّفاً في الغالب** — فتُقرأ بمعرّفها (`GET /contacts/{id}/`)
مرّةً لكلّ جهةٍ في الدورة، أو من فاتورةٍ حملتها، ويُحفظ المعرّف
(`wafeq_payments.contact_id`). **وحين لا يُعرف الدافع** يُرشَّح للطراز أحدثُ
٤٠ قضيةً مفتوحة **بأسماء موكّليها** — وكان المرشَّحُ «ما بقي عليه شيء»، وأكثرُ
القضايا بلا أتعابٍ مكتوبة، فتفرغ القائمةُ ولا يُسأل الطرازُ أصلاً، بصمت.

و**«اربط بالذكاء الاصطناعي الآن»** يعيد المطابقة على المخزَّن «بلا قضية» بلا
قراءة وافق من جديد، ويُضغط حتى لا يبقى شيء. والحصيلةُ تقول لماذا لم يُسأل
الطراز (مطفأ، بلا مرشّحين، بلغ السقف). والطرازُ يُشغَّل ويُطفأ بمفتاح
«التلخيص الآليّ» نفسِه، ونتيجتُه تبقى **اقتراحاً تؤكّده**.

**وأسماءُ حقول ردّهم لم تُقرأ من مرجعٍ مؤكَّد** عند كتابة القارئ
(`worker/lib/wafeq/api.js`)، فهو يقرأ كلَّ حقلٍ من أسمائه المحتملة. و«اختبار
الاتصال» يعرض **أسماءَ الحقول لا قيمَها** لصفحةٍ واحدة — فإن ظهر اسمٌ آخر
عُدِّل هناك وحده.

والترتيب: `اختبار الاتصال ← معاينة ← مزامنة ← ثم تُفتح الآلية` — والآليةُ كلَّ
ساعة مع بيسكامب، ولا تُفتح قبل مزامنةٍ يدويةٍ ناجحة.

## تعارضُ المصالح

لكلّ قضيةٍ **أطرافٌ خصم** (`cases.opposing_parties`، هجرة `0020`): اسمٌ ورقمُ
هويةٍ أو سجلٍّ اختياريّ. تُكتب من نافذة القضية، وتُقرأ من «بيانات المشروع» تحت
«الخصم» و«الخصوم» و«الطرف الخصم» و«الطرف الآخر» — **لا «المدعى عليه»** بقصد:
المكتبُ يترافع عن هذا مرّةً وعن ذاك أخرى، فالعنوانُ قد يسمّي موكّلَنا نفسَه.
ويدخل الدمجَ الثلاثي، والمنصةُ المعتمدة.

والفحصُ في الجهتين (`worker/lib/conflicts.js`، `GET /api/conflicts`):

- عند إضافة **عميلٍ أو محتمل**: أخصمٌ هو في قضيةٍ لموكّلٍ عندنا؟
- عند تسمية **خصمٍ**: أموكّلٌ هو عندنا؟

**تنبيهٌ لا منع** — القضيةُ قد تكون منتهية، والاسمُ قد يكون اسمَ غيره. ورقمُ
الهوية أو السجلّ **قاطع**، والاسمُ يُقال «يُراجَع» بمقارنةِ هوية الموكّل نفسِها
(`basecamp/names.js`): المختصرُ من الأتمّ، والابنُ ليس أباه. والمؤرشفُ داخلٌ
في الفحص ويُعلَّم.

## البريد — عبر Resend

Workers لا تتكلّم SMTP، فالإرسالُ من الخادم بـ`fetch` إلى Resend
(`worker/lib/mail.js`). ويلزمه سرّان — **سرّان لا متغيّران**: النشرُ يكتب
متغيّراتِ `wrangler.toml` فوق ما ضُبط في اللوحة، والأسرارُ تبقى:

```bash
wrangler secret put RESEND_API_KEY
wrangler secret put MAIL_FROM        # «ناف <no-reply@naflaw.sa>»
```

ونطاقُ المُرسِل يُوثَّق مرّةً عند Resend (سجلّات DNS)، وإلا رُدّت الرسائل
`rejected`. و`الإعدادات ← البريد الإلكتروني` تقول حالةَ الربط وترسل رسالةً
تجريبية. وغيابُ أحدهما غيابُ الربط: لا يُرسل شيء، **ولا يُسقط ذلك حفظاً**.

وما يُرسل (`worker/lib/notify.js`):

| الرسالة | متى | لمن |
|---|---|---|
| عميلٌ / قضيةٌ / محتملٌ جديد، دفعةٌ مسجَّلة | بعد الحفظ | من اشترك في نوعها **ويملك قراءةَ ما يُبلَّغ عنه** — والفاعلُ لا يُبلَّغ بما فعل |
| متابعاتُ اليوم | الثامنة صباحاً بالرياض، مرّةً في اليوم | المشتركون في «المتابعات» |
| التقريرُ الأسبوعيّ | صباحَ الأحد | المسؤولون المشتركون في «التحديثات» |
| دعوةُ اجتماع Zoom | عند إنشائه | المدعوّون — والنسخُ باقٍ |

**وجرسٌ في الترويسة** (هجرة `0023`): كلُّ إشعارٍ يُكتب بنداً لكلّ مستلم **ربط
البريدُ أم لم يُربط** — بالقواعد نفسِها: من اشترك ويملك القراءة، والفاعلُ لا
يُبلَّغ. والبندُ يفتح شاشتَه ويُعلَّم مقروءاً، والعضوُ لا يرى بنودَ غيره ولا
يعلّمها. ويُقرأ كلَّ دقيقة، وما مضى عليه تسعون يوماً يُحذف.

**والتقاريرُ المخصّصة تُجدوَل** من «منشئ التقارير» (هجرة `0022`،
`worker/lib/report-schedule.js`): يومياً أو صباحَ الأحد أو أوّلَ الشهر، الثامنةَ
بالرياض ومرّةً في دورتها. أوّلُ خمسين صفاً جدولاً في الرسالة والتقريرُ كلُّه CSV
مرفقاً. **ولا يتلقّاه إلا عضوٌ يملك قراءةَ التقارير ويرى هذا التقرير** (عامّاً أو
له)، والبريدُ الخارجيّ لا يكتبه إلا مسؤول.

والاشتراكُ تفضيلاتُ كلّ عضوٍ في `الإعدادات ← الإشعارات`. ونصُّ الرسائل يُهرَّب
قبل أن يُدرج: اسمُ موكّلٍ فيه `<` لا يصير وسماً في بريد غيره.

وإعدادُ SMTP القديم لم يُمسّ في القاعدة؛ إنما لم يعد يُقرأ، و`EmailSettings.tsx`
باقٍ في المستودع ولا تفتحه الشاشة.

## استيرادُ القضايا

`الإعدادات ← استيراد البيانات ← استيراد القضايا`: قالبٌ عربيّ يُنزَّل ويُملأ ويُرفع
CSV. **ومعاينةٌ أوّلاً لا تكتب حرفاً** — كم قضيةً تُنشأ، وكم عميلاً يُنشأ ويُربط،
وكلُّ صفٍّ مرفوضٍ أو منبَّهٍ عليه بسببه — ثم «تنفيذ» يُوقع ما عُرض
(`POST /api/cases/import`، `worker/lib/case-import.js`).

- **العميلُ يُطابَق بالهوية ثم بالاسم الموحَّد** — بـ`findClient` نفسِها التي في
  مزامنة بيسكامب — **وإن لم يوجد يُنشأ**، مرّةً لقضاياه كلِّها في الملفّ. واسمٌ
  يشبه عميلاً بلا هويةٍ تفصل يُنشأ ويُقال، ولا يُدمج.
- **رقمُ القضية** مكرّراً في الملفّ أو موجوداً في المنصة يُردّ صفُّه.
- **الحالةُ والنتيجة** تمرّان بمفردات «بيانات المشروع» (والجذر: «ربحانة» تُفهم)،
  وما لم يُفهم لا يُكتب ويُقال. ونوعُ الأتعاب رمزاً أو بوجهه العربي.
- **المحصَّلُ في الملفّ يصير دفعةً افتتاحية** كما في الهجرة `0018`.
- **والمحامي** يُطابَق بعضوٍ مفعَّل، و**الخصومُ** تُقرأ كما تُقرأ من بيسكامب.
- ويلزمه تصريحا **إنشاء القضايا والعملاء معاً**، وحدُّ الملفّ ٥٠٠ صفّ.

## المحامي المسؤول

لكلّ قضيةٍ **محامٍ مسؤولٌ واحد** (`cases.lawyer_id`) و**فريقٌ اختياريّ**
(`cases.team`)، هجرة `0021`. **والرؤيةُ لا تتبدّل به**: الكلُّ يرى الكلّ،
وللمحامي في شاشة القضايا تصفيةُ «قضاياي» (مسؤولاً أو في الفريق) و«بلا محامٍ».
واللوحةُ تعرض **حِملَ المحامين** — القضايا المفتوحة لكلٍّ منهم — ولا يبلغ ذلك
شاشاتِ العرض: أسماءُ أعضاء.

**والمحامون قائمةٌ من الإعدادات** (`الإعدادات ← المحامون`، جدول `lawyers`،
هجرة `0028`) — لا من حسابات المنصة: من المحامين من لا يدخلها. ولكلٍّ حسابٌ
اختياريّ (`member_id`، حسابٌ لمحامٍ واحد) تعمل به «قضاياي» لصاحبه. ومن عليه
قضايا يُوقف ولا يُحذف — يختفي من الاختيار وتبقى قضاياه باسمه. والترحيلُ زرع
القائمة بالأعضاء الذين كانوا محامين أو في فرق القضايا **بمعرّفاتهم نفسِها**،
فلم يتبدّل صفٌّ في القضايا.

ومن بيسكامب واستيراد Excel: اسمُ «المحامي المسؤول» **يُطابَق بمحامٍ مفعَّل**
(بالاسم الموحَّد، والمختصرُ من الأتمّ) فيُكتب معرّفُه. وما لم يُطابَق أو
طابق اثنين **لا يُكتب**، ويُفتح له في «يستحقّ نظرك» سؤالُ «محامٍ لم يُعرف» يُختار
فيه المحامي. والمنصةُ المعتمدة: محامٍ بُدِّل بيدٍ لا تدهسه دورة.

## نوعُ العمل و«جارية»

«منظورة» و«قيد المعالجة» كانتا حالتين لمعنًى واحد، فصارتا **«جارية»**
(`in-progress`، هجرة `0028` ومعها صورةُ المزامنة). والفرقُ الحقيقيّ **نوعُ
العمل** (`cases.work_kind`): **قضيةٌ منظورة** أمام جهة، أو **عملٌ قانونيٌّ
مستمرّ** (عقود، استشارات، تأسيس). ويُختار في نافذة القضية، وغيابُه «تلقائي»:
جهةٌ مختصة أو رقمٌ لديها أو نوعٌ يبدأ بـ«قضية» منظورة، وما سواها عملٌ قانوني
(`worker/lib/work-kind.js` ونسختُه `src/lib/work-kind.ts`).

## فتراتُ لوحة التحكم

فوق اللوحة فلترُ فترة: **جاهز** (هذا الأسبوع والماضي، والشهر، والربع، والعام —
الحاليّ والماضي) و**مخصّص** (سنةٌ أو ربعٌ أو شهرٌ أو أسبوعٌ بعينه، أو من تاريخ إلى
تاريخ). ويُذكر لكلّ متصفّح. والفترةُ تاريخان شاملان إلى `GET /api/stats?from&to`
(`readRange` في `worker/lib/queries.js`)، وكلُّ رقمٍ يُقارَن **بالفترة السابقة
المساوية**: الأشهرُ الكاملة بالأشهر السابقة عدداً (الربعُ بالربع، والسنةُ
بالسنة)، وما سواها بالأيام.

وما يتبع الفترة: العملاءُ والمحتملون بـ«عميلٌ منذ» فيها، والقضايا بفتحها فيها،
ونسبةُ الكسب بما حُسم فيها، والمحصَّلُ بدفعاتها، والتطوّعيةُ بفتحها. وما هو
**الآن** يبقى الآن ويُسمّى بذلك: الجاري، والمستحقّات، وحِملُ المحامين. وبلا
فترة: الكلّ، والمؤشّرُ آخرُ ثلاثين يوماً عمّا قبلها، والمحصَّلُ هذا العام.

**ونسبةُ كسب القضايا** = (الرابحة + التسوية/الصلح) ÷ المحسومة (ما له نتيجة).

## لوحةُ التحكم تُنقر

البطاقاتُ والرسمان وصفوفُ حِمل المحامين تفتح شاشتَها **بالتصفية المناسبة**:
«قضايا منظورة» و«أعمال قانونية مستمرة» تفتحان القضايا الجارية بنوعها، و«معدل
الربح» المكتملة، وعمودُ حالةٍ قضاياها، وقطعةُ نوعِ عميلٍ عملاءَه، واسمُ محامٍ
قضاياه. والتصفيةُ تُحمل في `App.tsx` (`ViewFilter`) وتُمسح بالتنقّل من الشريط.

## القضايا التطوّعية

بعضُ القضايا والأعمال القانونية يقدّمها المكتب مجاناً تطوّعاً. فـ«نوع
الأتعاب» فيه **«مجاني — تطوّعي»** (`fee_structure.type = 'pro_bono'`): تُخفى
معه حقولُ الأتعاب والتحصيل وعمولة المسوّق، وتُصفَّر عند الحفظ.

ولها **قيمةٌ تقديرية** بالريال و**ساعاتٌ** اختيارية (`pro_bono_value`
و`pro_bono_hours`) — ما كان المكتب سيتقاضاه. ومجموعُ السنة الجارية في بطاقة
اللوحة، و**تقريرُ المسؤولية الاجتماعية** في شاشة التقارير يُصدَّر Excel لسنةٍ
تُختار.

ولا تدخل الإيرادَ ولا العمولةَ المستحقّة في إحصاءات المسوّق — وإن بقي في
صفّها مبلغٌ من قبل أن تُعلَّم — وتُعدّ قضيةً ونتيجةً كغيرها. وتُعلَّم
«تطوّعي» في قائمة القضايا، ولها بطاقةٌ في لوحة التحكّم، وحقلُ «نوع الأتعاب»
في التقارير يعزلها. وهجرةُ `0016` تُلحقها بأنواع الأتعاب لمن حفظ قائمتَه بيده.

## لحظةُ إغلاق القضية

`cases.closed_at` — لحظةُ صيرورة الحالة «مكتملة»، وتُمحى إن رجعت القضية
مفتوحة. **تكتبه القاعدةُ بمشغّلين** (`migrations/0017`) لا الشيفرة: الحالةُ
تُكتب من النافذة والفعل الجماعي والمزامنة والحسم، وعمودٌ يُكتب في كلٍّ منها
يُنسى في أحدها. وبه يحمل «معدّل الربح» مؤشّرَه عن الشهر الماضي — **فرقَ نقاطٍ
لا نسبة**، ولا مؤشّرَ إن خلت إحدى النافذتين من قضيةٍ مغلقة.

وما أُغلق قبل الهجرة لا يُعرف متى أُغلق حقّاً، فيُقدَّر بآخر تعديلٍ له.

## المؤرشفُ خارجَ القياس

الأرشفةُ تُخرج الصفَّ من شاشته ولا تتلفه. وهو خارجٌ كذلك من `‎/api/stats‎`
ومن التقارير ومن استبصارات التحليلات ومن شاشة التحليلات ومن إحصاءات
المسوّق — موضعٌ واحدٌ للقرار في كلٍّ منها.

ويلزم من ذلك أنّ دمجَ عميلين مكرّرين — وهو يؤرشف المدموج — يصحّح الأرقام
كلَّها لا لوحةَ التحكّم وحدها.
