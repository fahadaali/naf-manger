# naf-manger — نظام إدارة العملاء

منصةٌ من منصات ناف. تُدير العملاء والعملاء المحتملين والقضايا والمسوّقين
والعمولات، وتعرض لوحةَ تحكّم وتحليلات.

والدخول **مركزيّ**: الهوية في `naf-id`، ولا كلمةَ مرورٍ في هذا المستودع
ولا في قاعدته. والتصميم من سجلّ `naf-ui` — لا لونَ يُنتقى هنا ولا مقاس.

---

## البنية

| الطبقة | التقنية |
| --- | --- |
| الواجهة | React 18 + TypeScript + Vite + Tailwind v4 |
| الخادم | Cloudflare Worker واحد — `worker/index.js` |
| القاعدة | Cloudflare D1 (SQLite) |
| الملفّات | Cloudflare R2 — الصور والمرفقات |
| الجلسات | Cloudflare KV — تقرؤها `naf-auth` |
| المصادقة | `naf-auth` مقابل المركز `naf-id` عبر OIDC |
| الرسوم | Chart.js + react-chartjs-2 |
| الأيقونات | Lucide — حصراً، وبالمعنى المسجَّل في `naf-icons.md` |

**Worker واحد لا Pages.** ترتيب `worker/index.js` هو الحراسة نفسها: ما قبل
`authenticate` مكشوف وما بعده محميّ، فكلُّ مسارٍ يُضاف يقع بعده ما لم
يُقصد غير ذلك صراحةً. و`run_worker_first = true` في `wrangler.toml` هو ما
يمنع تقديمَ `index.html` قبل الحارس.

```
worker/index.js        نقطة الدخول — الحارس والمسارات والأصول
worker/lib/            المنطق: الموارد والصلاحيات والاستعلامات والملفّات
src/                   الواجهة
src/registry/naf/      نسخةٌ من سجلّ naf-ui — لا يُعدَّل يدوياً
migrations/            هجرات D1، للأمام فقط
```

## التشغيل محلياً

```bash
npm install

# أسرار التطوير — انسخ المثال واملأ سرّ المنصة من لوحة المركز
cp .dev.vars.example .dev.vars

npm run dev        # خادم Vite للواجهة وحدها
npm run preview    # wrangler dev — الـWorker والحارس والقاعدة معاً
```

`npm run dev` يخدم الواجهة ولا يشغّل الـWorker، فنداءات `‎/api/*` تسقط فيه.
ولتجربة الحراسة والمسارات استعمل `npm run preview`.

```bash
npm run migrate:local    # تطبيق الهجرات على قاعدة D1 المحلية
npm run migrate:remote   # وعلى البعيدة
```

## قبل الدفع

```bash
npm run typecheck   # tsc — يمسك ما لا يمسكه البناء
npm run lint        # eslint
npm test            # على SQLite فعلية، ويحرس خصوصية خلاصة التحليلات
npm run build
```

**البناء وحده لا يكفي.** `esbuild` داخل Vite يحوّل ولا يفحص الأنواع، فخطأٌ
مثل `TS2440` (تصادمُ اسمٍ مستورَد مع مُعرَّف محلّي) يمرّ منه صامتاً — وقد
مرّ فعلاً إلى الإنتاج مرّةً، وكان يجعل شاشةَ الإعدادات تستدعي نفسها بلا
توقّف حتى يعلق المتصفّح. ولذلك يمرّ سير النشر بـ`lint` و`typecheck` قبل
`build`.

## النشر

يقع في `.github/workflows/deploy.yml` عند الدفع إلى `main`: تُنشأ الموارد
إن لم تكن — D1 وKV وR2 — ويُحقن معرّفاها في `wrangler.toml`، ثم تُطبَّق
الهجرات ويُبنى ويُنشر.

والسرّ الوحيد يُضبط مرّةً بيدك، ولا يُكتب في `wrangler.toml` أبداً:

```bash
wrangler secret put AUTH_CLIENT_SECRET
```

ومتغيّرات `wrangler.toml` غيرُ السرّية: `PLATFORM_ID` و`AUTH_ISSUER` و
`DEFAULT_ROLE` و`BOOTSTRAP_ADMIN_EMAIL` — وشرحُ كلٍّ منها فوقه هناك.

## المصادقة والصلاحيات

**المصادقة مركزية والصلاحيات موزّعة.**

المركز يقرّر من يدخل، ولا يقرأ دور العضو في هذه المنصة في أي قرار. وما
يملكه الداخل يقرّره جدول `members` في D1 وحده، وافتراضاتُ الأدوار في
`worker/lib/roles.js` — وهو الحاكم في كل طلبٍ محروس.

والأدوار ثلاثة: `admin` و`lawyer` و`staff`.

**ولا يُنشأ عضوٌ من هذه المنصة.** الصفّ يُدرَج بأول دخولٍ من المركز
ومفتاحُه `sub` القادم منه، ومن بعده تُدار الترقيةُ والإيقاف من شاشة
المستخدمين. وصاحبُ `BOOTSTRAP_ADMIN_EMAIL` يُنشأ `admin` عند أول دخوله —
وينشئ ولا يرقّي، فيلزم ضبطُه قبل ذلك الدخول.

## ربطُ Zoom

اجتماعاتُ Zoom تُنشأ من الـWorker لا من المتصفّح: سرُّ المزوّد لا يُشحن في
حزمةٍ يقرؤها كل زائر. وتلزمه ثلاثةُ أسرارٍ من تطبيق **Server-to-Server
OAuth** في لوحة مطوّري Zoom:

```bash
wrangler secret put ZOOM_ACCOUNT_ID
wrangler secret put ZOOM_CLIENT_ID
wrangler secret put ZOOM_CLIENT_SECRET
```

وغيابُ أحدها غيابُ الربط: المسار يردّ `not_connected` والشاشة تقول «غير
مربوط»، ولا يُفبرك اجتماع.

## شاشات العرض

`الإعدادات ← العرض والمراقبة` تُنشئ رابطاً لكل شاشة:
`https://<النطاق>/display/<رمز>`. يُفتح بلا تسجيل دخول ويُبطَل بالحذف.

وما خلفه **إحصاءاتٌ مجمَّعة وحدها** — أعدادٌ ونسب — ولا اسمَ عميلٍ ولا رقمَ
قضية ولا مبلغ. والرابط يعيش في شاشةٍ يراها كلُّ من يمرّ، فما خلفه يجب أن
يحتمل ذلك.

## قراءةُ التحليلات (Workers AI)

فوق شاشة التحليلات لوحٌ يقرأ الأرقام نيابةً عمّن يفتحها: أين يتسرّب
المحتملون، وأيُّ نوعِ قضايا يربح، وأيُّ شهرٍ تراجع.

والاستدلال على **Workers AI** — داخل شبكة Cloudflare نفسها التي تحمل
المنصة وقاعدتَها. فلا مفتاحَ مزوّدٍ يُدار ولا يُسرَّب، ولا خروجَ إلى طرفٍ
ثالث. وهو ارتباطٌ `[ai]` في `wrangler.toml` لا سرّ، فلا شيءَ يُضبط باليد.

**وما يُمرَّر إليه أرقامٌ مجمَّعة وحدها** — لا اسمَ عميلٍ ولا رقمَ هوية ولا
رقمَ قضية ولا بريدَ أحد ولا مبلغاً منسوباً إلى شخص. والخلاصةُ كلُّها في
دالّة `buildDigest` في `worker/lib/insights.js`، تُقرأ في موضعٍ واحد. وهذا
مكتبُ محاماة: الشرطُ لا يُترك لتعليقٍ يقوله، فـ`tests/insights.test.mjs`
يزرع القاعدة بأسماءَ وبُرُدٍ وأرقامِ قضايا ثم يفتّش نصَّ ما وصل الطراز
حرفيّاً، وسقوطُه يوقف النشر.

والناتج يُخبَّأ ببصمةِ الأرقام: أرقامٌ لم تتبدّل لا تُستدلّ مرّتين، وتبدُّلُ
رقمٍ واحدٍ يُبطل الخبيئة. و«إعادة القراءة» تتخطّاها.

والطراز في `AI_MODEL` — يُبدَّل من `wrangler.toml` بلا نشرِ شيفرة، والبدائل
مذكورةٌ فوقه هناك.

## الربط ببيسكامب

`الإعدادات ← إدارة المستخدمين والبيانات ← الربط ببيسكامب`. وبياناتُ العملاء
القديمة هناك موزّعةٌ على مشاريع: بعضُها إداريٌّ داخلي، وبعضُها عملُ عميل.

**والذي يفرّق بينهما ملفّ «بيانات المشروع»** — وهو في كل مشروعِ عميل. فوجودُه
يرجّح `client` وغيابُه `internal`، **والترجيحُ اقتراحٌ لا حكم**: الشاشة تعرضه
ويصنّف من يفتحها بيده، وما صنّفه لا ينقضه مسحٌ لاحق.

**واسمُ الملفّ يتبدّل** — وقد تبدّل: كان «ملخص القضية». فالعناوينُ المقبولة
قائمةٌ تُعدَّل من الشاشة وفيها الاسمان معاً، لأنّ مشاريعَ سنينَ ماضية لم
يُعَد تسميةُ ملفّاتها. وملفٌّ عُرف مرّةً لا يضيع بإعادة تسمية: معرّفُه عند
بيسكامب لا يتبدّل، فيُعرف به ويُقال في الشاشة إنّ عنوانَه الجديد كذا —
ليُضاف إلى المقبولة بدل أن ينقطع الاستيراد صامتاً.

والاتّجاه واحد: **يُقرأ من بيسكامب ولا يُكتب فيه**. فصلاحيةُ القراءة تكفي،
وخطأٌ في المنصة لا يُفسد وثيقةً أصلية عند العميل.

يلزمه تطبيق OAuth يُسجَّل مرّةً في
[launchpad.37signals.com/integrations](https://launchpad.37signals.com/integrations)
برابط عودة `https://<النطاق>/api/basecamp/callback`، ثم ثلاثةُ أسرار.

**ورابطُ العودة يُطابَق حرفاً.** والمنصة تشتقّه من العنوان الذي فُتحت منه
(`url.origin` في `basecamp/oauth.js`) — فمن يربط من `crm.naflaw.sa` يلزمه
`https://crm.naflaw.sa/api/basecamp/callback` مسجَّلاً هناك. والربطُ من
عنوان `workers.dev` أصلٌ آخر، فيحتاج تسجيلَ رابطه هو.

```bash
wrangler secret put BASECAMP_CLIENT_ID
wrangler secret put BASECAMP_CLIENT_SECRET
wrangler secret put BASECAMP_TOKEN_KEY   # مفتاحٌ من عندك، تُعمَّى به الرموز المحفوظة
```

وغيابُ أحدها غيابُ الربط: الشاشة تقول «لم يُسجَّل التطبيق» وتسمّي الناقص، ولا
يُستورد شيء. وتبديلُ `BASECAMP_TOKEN_KEY` يُبطل الربط القائم فيُطلب ربطٌ
جديد — ولا يُفقد شيءٌ ممّا استُورد.

#### أو من لوحة Cloudflare، بلا طرفيّة

`dash.cloudflare.com ← Compute (Workers) ← naf-manger ← Settings ←
Variables and Secrets ← Add`

ولكلٍّ من الثلاثة: النوع **Secret**، ثم الاسم، ثم القيمة، ثم **Deploy**.
واختيارُ `Secret` لا `Text` هو ما يمنع ظهور القيمة بعدها في اللوحة أو في
`wrangler` — وسرُّ التطبيق يُعرض مرّةً عند بيسكامب ولا يُعرض بعدها.

والأسرارُ تبقى عبر النشرات: سيرُ النشر يُحدِّث الشيفرة ولا يمسّها. ولو
مُحيت يوماً فالعَرَض ظاهر — الشاشة تعود تقول «لم يُسجَّل التطبيق».

ورمزا الوصول والتجديد يُحفظان في D1 معمَّيَين بـ AES-GCM. وذلك يحمي من تسرّب
نسخةٍ من القاعدة، لا من Workerٍ مخترَق — من ملك تنفيذ الشيفرة ملك المفتاح معها.

### ترتيب العمل

`اتّصال ← مسحٌ وتصنيف ← خريطةُ حقول ← معاينة ← تنفيذ ← ثم تُفتح الآلية`

**ولا تُكتب في قاعدة العملاء كلمةٌ قبل معاينةٍ رآها صاحبُ المكتب.** المعاينة
تقرأ الملفّات وتقول ما سيقع — كم عميلاً يُنشأ، وأيُّ قضيةٍ تُحدَّث وفي أيّ
حقل، وأيُّ مشروعٍ تعذّر ولماذا — ولا تكتب حرفاً.

### خريطة الحقول

«بيانات المشروع» حقولٌ معنونة: `اسم العميل: …`. والعناوين تختلف بين مكتبٍ
وآخر، فتُربط من الشاشة بحقول المنصة وتُحفظ في `system_settings` — بلا نشرِ
شيفرة. والتشكيلُ والتطويلُ وصورُ الألف لا تُهمّ: تُطابَق موحَّدةً،
فـ«ملخّص القضيّة» و«ملخص القضيه» عنوانٌ واحد.

والافتراضُ يعرف صيغتَي العناوين: «رقم المشروع» و«رقم القضية»، و«نتيجة
المشروع» و«نتيجة القضية» — فالملفّ الجديد والقديم يُقرآن بلا إعادة ضبط.

**والحقول المقروءة**: اسمُ العميل (أو اسمُ الشركة) ورقمُ هويته ونوعُها
وجوّالُه وبريدُه و**نوعُ العميل** وسجلُّه التجاري و**مسؤولُ التواصل**
و**ملاحظاتُه**؛ ورقمُ المشروع ونوعُه وموضوعُه وحالتُه و**نتيجتُه**
و**ملاحظاتُه**.

و«مسؤول التواصل: أحمد الغامدي - 0551234567» سطرٌ فيه ثلاثة: اسمٌ ورقمٌ
وربما هوية — تُقرأ إلى `legal_representative`، ولا يُحشر السطرُ كلُّه في
خانة الاسم.

و**الملاحظاتُ تُقرأ ولو كانت أسطراً تحت عنوانها**:

```
الملاحظات:
- العميل يفضّل التواصل مساءً
- الأوراق الأصلية عند وكيله
```

فعنوانٌ تُرك فارغاً يأخذ ما تحته حتى العنوان التالي. وعنوانٌ حمل قيمةً لا
يأخذ ما بعده — وإلا دخل ذيلُ الملفّ في حقلِ موكّل كأنه منه.

وعنوانٌ في الملفّ بلا مقابلٍ في الخريطة **يُعرض في المعاينة** — فلا يضيع
حقلٌ صامتاً لأنّ أحداً لم يعرف أنه هناك.

### المزامنة المستمرّة والدمج الثلاثي

تعمل كلَّ ساعة (`[triggers]` في `wrangler.toml`)، ولا تُفتح إلا بعد تنفيذٍ
يدويٍّ ناجح. تلتقط المشروع الجديد فتصير قضيةً في المنصة، وتحدّث ما تبدّل.

ولكل حقلٍ ثلاثُ قيم: ما في المنصة الآن، وما كتبته المزامنة آخرَ مرّة، وما في
بيسكامب الآن. ومنها يُعرف من تحرّك:

| المنصة | بيسكامب | العمل |
|---|---|---|
| كما تركناها | تبدّل | **يُكتب** بلا إزعاج |
| كما تركناها | كما هو | لا شيء |
| مسّتها يد | كما هو | يُترك — المنصة أحدث |
| مسّتها يد | تبدّل | **يقف**: يُسجَّل بالقيمتين في «الاختلافات» ولا يُكتب |

فتصحيحٌ كتبه المحامي لا يُمحى صامتاً. والاختلافات تُحسم من الشاشة: «خذ من
بيسكامب» أو «أبقِ ما في المنصة» أو «تجاهل».

**والعميلُ يُدمَج كقضيته.** كان يُكتب مرّةً عند إنشائه ثم لا يُعاد إليه —
فمكتبٌ يضيف اليوم «نوع العميل» و«الملاحظات» إلى ملفّات موكّليه القدامى
يزامن فلا يقع شيء. وصار حقلُه يُدمج بالجدول أعلاه، بفارقٍ واحد في أوّل
لقاء: العميلُ قد يكون كُتب في المنصة قبل بيسكامب بسنة، فما كان فارغاً
يُملأ صامتاً، وما فيه قيمةٌ تخالف **يقف اختلافاً ينتظر قرارك** — لا يُدهس
ولا يُهمَل. و«فرد» في نوع العميل تُعدّ فراغاً: هي افتراضُ العمود لا قرارَ
أحد.

**والحقول التي لا تمسّها المزامنة أصلاً**: الأتعاب والعمولات والمسوّق — ليست
في «بيانات المشروع»، وتُدار في المنصة وحدها.

### هويّةُ الموكّل — واحدٌ وإن اختُلف رسمُ اسمه

«محمد خالد عبدالله القحطاني» و«محمد خالد القحطاني»: **رقمُ الهوية هو
الفصل**. إذا اتّحد فهو موكّلٌ واحد مهما اختلف رسمُ الاسم — ولا يُنشأ له
ملفٌّ ثانٍ، ولا يقف اسمُه اختلافاً في كل مزامنة. ويُكتب الأتمُّ من
الاسمين: هو ما يُكتب في الوكالة والصحيفة.

والمقارنةُ تُسقط ما لا يفرّق: أداةَ التعريف («القحطاني» و«قحطاني»)،
و«بن»، ورسمَ «عبد الله» و«عبدالله».

**وبلا رقم هوية يُقترح ولا يُدمج.** «محمد القحطاني» اسمُ عشرة، ودمجُ
ملفَّي موكّلين مختلفين خطأٌ لا يُكشف إلا بعد أن يُبنى عليه — توكيلٌ في
ملفّ غيره، وقضيةٌ تُنسب إلى من ليس صاحبَها. فتقول المعاينة «يشبه عميلاً
قائماً: فلان — راجِعه»، ويبقى الحكمُ لمن يقرأ.

ويُميَّز الأخُ من أخيه والابنُ من أبيه: الاحتواءُ لا يكفي، بل يلزم اتّحادُ
الاسم الأول والأخير معاً — فـ«خالد عبدالله القحطاني» ليس اختصاراً لـ«محمد
خالد عبدالله القحطاني».

### التلخيصُ الآليّ عند الاستيراد

يعمل من أوّل نشرة، ويُطفأ من الشاشة. وهو ثلاثة أشياء:

- **ملخّصُ كلّ قضية** — سطرٌ يُكتب في حقل `ai_summary`.
- **ملخّصُ قضايا كلّ موكّل** — «ثلاثُ قضايا تجارية، اثنتان مكتملتان»،
  يُبنى من صفوف قضاياه في المنصة لا من ملفٍّ واحد.
- **اقتراحُ نوع القضية** حين يخلو منه الملفّ — **من قائمة «تكوين النظام»
  وحدها**. فما ردَّه الطراز خارجَها يُردّ، وأسوأُ ما يقع أن يبقى الحقل
  «غير محدّد» كما كان. ويُعلَّم في المعاينة «مقترَح» ليُراجَع.

**وفي حقلٍ مستقلٍّ عن الملاحظات**، مسمّىً «ملخّصٌ آليّ» في نافذة القضية
والعميل. فالملاحظاتُ يكتبها المحامي ويأتي فيها ما في «بيانات المشروع»،
ونصٌّ آليٌّ لو دخلها لاختلط بما كتبه إنسان — فيُقرأ بعد شهرٍ كأنه منه،
ويدخل الدمجَ الثلاثي فيبدو أنّ «يداً مسّت الحقل» في كل دورة.

**ولا يُخترع حقل.** الطراز يُلخّص ما أُعطي ويصنّف من قائمةٍ مغلقة — ولا
يملأ اسماً ولا رقماً ولا تاريخاً. تلك تُقرأ بقاعدةٍ تُخطئ خطأً ظاهراً أو
تصيب، لا بترجيحٍ يُنتج قيمةً معقولة لم تُكتب قطّ.

#### ما يخرج إلى الطراز

| يخرج | لا يخرج |
|---|---|
| اسمُ الموكّل ونوعُه | رقمُ الهوية |
| نوعُ القضية وموضوعُها وحالتُها ونتيجتُها | الجوّال والبريد |
| ملاحظاتُ القضية | الأتعابُ والعمولات |

والاستدلال على **Workers AI** — شبكةُ Cloudflare نفسُها التي تحمل القاعدة،
بلا مفتاحِ مزوّدٍ خارجيّ ولا رحلةِ خروج. والطراز في `AI_MODEL`.

وهذا أوسعُ ممّا يخرج إلى استبصارات التحليلات — تلك أرقامٌ مجمَّعة وحدها،
بلا اسمٍ ولا نصّ، ولم يتغيّر ذلك.

#### والاستدلالُ لا يتكرّر ولا يُسقط شيئاً

تُحفظ بصمةُ النصّ الذي لُخِّص: ما دام هو هو فالملخّصُ هو هو، فلا تدفع
مزامنةُ كلِّ ساعةٍ ثمنَ تلخيصٍ مكرّر. وللدورة سقفٌ (٢٥ استدلالاً)، وما
زاد يُلخَّص في التي تليها ويُقال عددُه — فلا يُظنّ أنّ الميزة عطلت.

وسقوطُ الاستدلال لا يُسقط الاستيراد: تُكتب القضيةُ بلا ملخّص، ولا تُثبَّت
بصمةٌ على سقوطٍ — فتُعاد المحاولةُ في الدورة القادمة.

### ما يقع للأرقام الناقصة

ملفٌّ بلا رقم هوية أو بلا رقم قضية لا تُسقَط قضيتُه: يُولَّد رقمٌ **ثابت**
مشتقٌّ من معرّف المشروع (فمزامنةٌ ثانية تجد الصفَّ ولا تُنشئ ثانياً)،
ويُعلَّم في المعاينة «يحتاج تصحيحاً». والملفُّ بلا اسمِ عميلٍ يُردّ بسببٍ
مسمّى ولا يُكتب منه شيء.

ومشروعان لعميلٍ واحد → **عميلٌ واحد وقضيتان**، لكلٍّ رابطُ مشروعها. وهو
عينُ ما تعرضه شاشةُ العميل أصلاً.

## ما لم يُبنَ بعد

يُذكر هنا صراحةً كي لا تُقرأ شاشةٌ على أنها تعمل:

- **إرسال البريد** — Workers لا تتكلّم SMTP، ويلزم مزوّدٌ يتكلّم HTTP.
  شاشة البريد تحفظ الإعدادات وتقول «غير مربوط»، ودعوةُ الاجتماع تُنسخ
  وتُرسَل باليد.
- **المساعد الذكي** — لا شاشةَ له: «المحامي الذكي» حُذف وخدمتُه في منصةٍ
  أخرى من منصات ناف. و`src/services/geminiService.ts` يبقى وثيقةَ قرارٍ لمن
  يربط مساعداً لاحقاً — النداء من الـWorker ومفتاحُه سرٌّ هناك، لا `VITE_*`
  في حزمة المتصفّح.
- **إشعارات فعلية** — تفضيلاتُها تُحفظ في صفّ العضو، ولا مُرسِل لها بعد.
- **جدولةُ التقارير** — الجدولة قائمةٌ الآن لمزامنة بيسكامب، ويُضاف إليها
  تشغيلُ التقارير حين يُبنى.
- **استيراد القضايا** — العملاء والمحتملون يُستوردان؛ والقضية تشير إلى عميل
  بمعرّفه، ومطابقتُه من ملفٍّ قرارٌ لم يُتَّخذ.
- **مصدرُ بياناتٍ مركَّب في التقارير** (`mixed`) — الوصلُ بين جدولين.
